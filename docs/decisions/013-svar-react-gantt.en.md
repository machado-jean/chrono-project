# ADR 013 — SVAR React Gantt as the temporal projection

- Status: accepted
- Date: 2026-08-28

## Context

Phase 4 requires a Gantt with hierarchy, bars, progress, FS dependencies,
summary tasks, time scale, zoom, and selection. `AGENTS.md` prohibits building a
complete renderer without justification and requires evaluation of licence,
maintenance, TypeScript, React, performance, editing, accessibility, bundle,
and customisation.

The TypeScript scheduler and SQLite are already the sources of truth. A Gantt
library must not recalculate or persist a second schedule in parallel.

## Alternatives evaluated

### SVAR React Gantt 2.7.1

- MIT licence and active public repository;
- React component with TypeScript declarations and React 18-or-newer support;
- hierarchy, summary tasks, dependencies, progress, scales, and virtualisation;
- sufficient events and properties for selection, zoom, and cell highlighting;
- grid exposed to assistive technology, while Chrono Project provides its own
  panel for safe selection and editing;
- Gantt CSS and code can be loaded on demand.

### Frappe Gantt 1.2.2

- MIT licence and small bundle;
- imperative integration, without a React component or hierarchy equivalent to
  the requirement;
- would require more project-maintained adaptation, focus, and accessibility.

### gantt-task-react

- simple React/TypeScript API;
- weaker maintenance and evolution signals for a structural dependency;
- lower fit for Phase 4 hierarchy and extensibility requirements.

## Decision

Adopt `@svar-ui/react-gantt` **2.7.1**, exactly pinned in `package.json` and
installed only in the project.

Chrono Project converts `Task` and `TaskDependency` to a transient projection;
no Gantt-specific entity is persisted. Beyond the side panel, final move, resize,
and link-creation events are intercepted through the renderer API. They are
validated by the domain, pass through the scheduler, and use the same
transactional operation as the Table; SVAR internal state is discarded and
reprojected after success or failure.

The final visual event is accepted to avoid immediately returning the bar to its
source position. Chrono Project persists movement, finish, and completion; on
failure it forces a new projection. Events with `eventSource`, internally
generated by SVAR when summaries update, remain inside the renderer and are
never persisted as user commands.

Chrono Project’s date-only contract treats finish as inclusive, while the
renderer treats `end` as exclusive. The adapter adds one civil day to finish
only in the projection and does not simultaneously send `duration`; useful
duration remains a separate informative field. This preserves weekends and
holidays in the exact visual extension of a bar.

Existing relations can be highlighted through a selector or click on the
official row hitbox. A new visual link accepts only zero-lag FS in the same
project. The successor must be a leaf; the predecessor can be leaf or summary.
Self-dependency, duplication, and cycles combined with hierarchy are rejected
before persistence. The context menu creates and removes relations; the Table
remains available for detailed editing. Other rows remain visible and selectable
when a relation is highlighted.

Free `AUTO` tasks may be moved or resized. For a task with a predecessor, full
movement automatically adjusts non-negative FS lag; the initial edge remains
protected. The final edge changes duration and the scheduler propagates the new
finish to successors. A closed lock blocks these gestures on `MANUAL` tasks
without preventing exact inspector editing. Summaries are not editable. The
inspector remains the keyboard-operable alternative.

Weekends and holidays are highlighted by the Chrono Project calendar. The
library’s PRO calendar or automatic scheduling is not adopted because it would
duplicate domain rules. Unscheduled tasks are reported and remain accessible in
the Table and panel selector.

Gantt and CSS load on demand when the view opens. In the Phase 4 final build,
the main chunk was about 255 kB, the Gantt chunk 260 kB before gzip, and the
specific Gantt CSS about 148 kB.

## Consequences

- Phase 4 gains a mature renderer without duplicating scheduling or persistence.
- The dependency adds its transitive SVAR packages to the lockfile.
- Interception requires integration tests ensuring drag/resize cannot bypass
  calendars, predecessors, manual tasks, or summaries.
- The Table remains the complete accessible reference; Kanban and the Gantt
  panel provide keyboard paths for essential actions.
- The **Dependency in focus** selector is a keyboard alternative to clicking a
  link and reduces visual crossings without maintaining a custom renderer.
- Library updates must repeat licence, compatibility, visual-regression, and
  bundle-impact evaluation.
